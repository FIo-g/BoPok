# AI 일정의 식당·숙소 연결 — 2026-11-04

이동주의 요청에 따라 확보된 장소 DB로 동선별 식당·숙소 자동 배치를 연결한다. 기존 AI 일정 생성·다시 짜기의 초안 처리 단계에만 적용하고, 걷는 시간·판정은 기존 계산 엔진에 맡긴다. 김태형의 AI 영역 변경이므로 PR 리뷰가 필요하다.

- 식사·카페·숙박 이름을 가진 빈 자리만 채운다. 이미 선택된 장소, 직접 지정한 좌표, 예약, 꼭 갈 곳은 보존한다.
- 처음부터 여러 날 일정을 만들 때는 마지막 날 전까지 숙박 자리를 추가한다. 붙여 넣은 일정이나 다시 짜기에 숙박일을 임의 추가하지 않는다.
- 같은 날의 앞뒤 장소 좌표로 후보를 찾고, DB의 장소 ID·이름·좌표를 사용한다. 이미 일정에 있는 장소를 중복 배치하지 않는다.
- 후보의 직선 거리·우회 거리는 대중교통 1.5km, 자가용·택시 5km 이내로 제한한다. 실제 이동 시간이나 접근성 보장이 아니며, 구간 계산·판정은 이후 기존 경로·엔진 단계에서 수행한다.
- 기존에 읽은 피할 음식 태그가 메뉴에서 확인된 후보는 자동 배치에서 제외한다. 메뉴나 태그가 없는 장소를 안전하다고 표시하지 않으며 기존 식단 주의 안내를 유지한다.
- 영업 여부, 예약 가능 객실, 가격, 좌석, 계단 상태를 추정하지 않는다. 확인할 후보가 없거나 조회가 실패하면 빈 자리를 유지한다.
- 후보 조회는 초안당 최대 4초 안에서 끝낸다. 추가 LLM 호출 없이 기존 DB 추천 서버 함수를 사용한다.
- 기존 사용자 여행은 자동으로 다시 저장하지 않는다. 사용자가 일정 생성·다시 짜기를 요청한 경우 기존 버전 저장 흐름을 따른다.

변경 경계는 `AiDeps.recommendServicePlaces`와 `fillRouteServices`다. 확인은 외부 API를 호출하지 않는 가짜 추천 함수로 수행한다.
