# 비용 저장·가족 공유 — 2026-11-04 이동주 결정

사용자는 비용을 여행 버전·일차별로 명시적으로 저장하고 같은 가족 그룹이 함께 조회하는 방식을 선택했다. 2026-11-02 범위 확장 설계 4.6을 이어받는다.

- 계산식: 확인한 항목을 1인 기준으로 합산하고 여유 20%를 표시한다. 미확인 금액·단위는 무료나 1인분으로 추정하지 않는다.
- 저장: 비용 저장 버튼을 누를 때 해당 버전·일차의 금액, 단위, 수량, 종류, 출처와 미완성 초안을 저장한다. 다른 버전이나 날짜로 자동 복사하지 않는다.
- 권한: 여행 그룹 구성원이 조회·수정한다. 로그인하지 않은 사람과 다른 그룹은 접근할 수 없다.
- 충돌: 읽어 온 revision이 현재 저장본과 일치할 때만 갱신한다. 먼저 저장한 가족의 값을 조용히 덮어쓰지 않는다. 충돌 시 입력값을 남기고 다시 불러오도록 안내한다.
- 일정: 저장한 버전의 동선·장소·인원과 일치하는 비용만 저장한다. 직접 고치는 중인 일정은 먼저 일정 버전을 저장하도록 안내한다. 기존 비용은 일행 수가 달라져도 자동 환산하지 않는다.
- API: `GET/PUT /api/trips/:id/versions/:vid/costs`, GET은 `?day=1`을 받는다. 공용 계약은 `src/lib/contracts/cost-plan.ts`다.
- DB: `version_cost_plans`의 `(version_id, day)`가 기본키다. 추가형 마이그레이션 `0006_trip-cost-plans`만 생성했다. `db.transaction()`을 사용하지 않는다.
- 배포: SQL이 없으면 기존 계산 화면을 유지하고 저장 준비 중으로 안내한다. 공유 DB 적용은 PR 승인·머지 이후 진행한다.

리뷰 대상은 김경선(여행 API·DB), 오하연(CostSlot·공용 계약), 김태형(비용 엔진·공용 계약)이다. 기존 사용자 여행·버전·건강정보는 이 개발 과정에서 변경하지 않는다.
